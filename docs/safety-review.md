# 发布前代码流程审查

审查覆盖图形界面、参数传递、目标识别、组件服务会话、系统文件检查器、镜像释放、引导写入、修复来源挂载和清理、取消及日志保存。

## 系统维护

组件检查和修复由 Windows 组件服务执行，应用不会自行删除组件存储、覆盖组件清单或重置维护数据库。离线目标会检查实际卷身份、可写状态和关键路径，拒绝把当前 Windows 作为离线目标，也拒绝通过重解析点访问关键维护路径。内部接口查询或操作失败时保留错误，不切换到另一种引擎来假报同一路径成功。

系统文件维护调用系统目录中的 `sfc.exe`。离线维护需明确提供目标和实际引导分区，拒绝宿主系统及其实际启动分区。结果分别核对自然退出、原始退出码和终端报告；输出不能确认时保持未知。修复之后独立进行完整验证。

## 镜像与引导

镜像释放拒绝当前 Windows 所在磁盘和实际启动磁盘，只允许已经准备好的空白 NTFS 分区。不包含格式化、自动搬迁旧系统、清空用户目录或失败后递归删除目标的操作。源映像保持只读，执行前后核对目标卷身份。便携式系统后处理只作用于新目标的离线注册表。

引导路径使用 Windows 的 BCDBoot，以及 BIOS 模式下的微软 bootsect。代码不包含引导扇区机器码，不直接写物理磁盘扇区，不创建固件启动项或调整固件顺序。工具参数明确指定目标；BIOS 工具要求名称、原始文件名及微软签名验证，且不使用强制卸载、全部卷或隐式系统卷参数。目标和引导分区必须位于同一个独立磁盘。

## 进程与资源生命周期

真实维护通过进程间互斥避免本程序并发写入。子进程只继承明确列出的通信句柄；父进程在异常情况下仍等待已启动的维护工作进程自然结束，再处理来源和目标映射。CBS 的待处理系统动作会阻止自动进入后续系统文件修复。

来源元数据使用独立副本读取；借用来源不因读取注册表而被写入。自建修复镜像只读挂载，清理只处理本任务拥有的挂载和空目录。不会自动接管其他挂载或递归删除挂载内容。临时盘符只在当前卷身份仍然匹配时移除，失败会记录并反映在完成状态中。

日志采用新建文件并保持句柄的方式保存，不在每条记录到达时重新打开可能被替换的路径。系统文件检查器的任务日志位于受限的新目录中；结果协议拒绝矛盾参数、重复或不完整结果，异常退出不被当作成功。

## 仍需遵守的边界

只应使用可信 Windows 安装介质和可信离线系统；离线组件维护需要加载该系统的维护堆栈。操作期间不应通过其他管理工具重新分区、替换卷映射或卸载来源。强行结束进程或断电仍可能遗留临时映射或不完整系统，本版没有跨崩溃自动恢复机制。

本审查说明代码的预期边界和已采取的保护措施。实际完成的测试及尚未验证的环境见 [validation.md](validation.md)，不以代码审查代替运行验证。
